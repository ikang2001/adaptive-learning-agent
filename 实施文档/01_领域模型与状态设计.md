# 领域模型与状态设计

## 1. 目标

本层负责定义整个系统的“事实结构”。

原则：

- 领域状态不能依赖具体 LLM；
- 所有重要状态必须可持久化；
- Agent 只能通过明确工具修改业务状态；
- 状态更新必须保留版本与原因；
- 后续算法升级时能够重新计算历史画像。

---

## 2.2 KnowledgeNode

自动控制原理知识树节点。

```text
KnowledgeNode
├─ knowledge_id
├─ parent_id
├─ level
├─ name
├─ description
├─ prerequisites[]
└─ version
```

要求：

- 支持层级；
- 支持前置知识；
- 支持后续调整知识树而不破坏历史数据。

## 2.3 StudentKnowledgeState


# 3. 领域事件

为了后续可持续更新，建议保留事件。

```text
StudentCreated
StudentScheduleUpdated
QuestionAttemptRecorded
TaskFeedbackSubmitted
KnowledgeMasteryUpdated
ErrorProfileUpdated
EfficiencyProfileUpdated
WeeklyPlanCreated
PlanTaskAdjusted
PlanReplanned
TrueExamCompleted
MockExamGenerated
MockExamCompleted
```

价值：

- 可审计；
- 可重放；
- 新算法可以重新计算 Student Model；
- 便于评测旧版本与新版本差异。

---

# 4. 状态更新约束

Agent 不允许直接：

```text
student.mastery = 0.8
```

必须通过工具：

```text
update_mastery(
    student_id,
    knowledge_id,
    evidence_ids,
    update_reason,
    strategy_version
)
```

并校验：

- 是否存在真实 attempt / feedback；
- evidence 是否属于该 student；
- 新值是否超出合法范围；
- 当前策略版本是什么。

---

# 5. 版本治理

所有会影响结果的核心状态都必须记录版本：

```text
knowledge_tree_version
school_profile_version
exam_profile_version
mastery_strategy_version
efficiency_strategy_version
planner_version
selector_version
prompt_version
model_version
```

否则未来修改算法后，无法解释：

> 为什么同样数据在两个月前和现在算出的掌握度不同？

---

# 6. 不要过早确定的部分

第一版不要把以下内容设计得过重：

- 精确的掌握度公式；
- 复杂贝叶斯知识追踪；
- 强化学习；
- 图神经网络知识状态；
- 多科联动。

先保证事件、状态、证据完整，后续算法可以替换。
