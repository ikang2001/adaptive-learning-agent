# 数据与知识库层实施

## 1. 本层目标

把非结构化资料转成可供业务层、Agent、Planner 使用的可信数据。

主要数据：

1. 目标院校历年真题；
2. 真题考点分类；
3. 题型分类；
4. 考频统计；
5. 自动控制原理讲义；
6. 教材/习题；
7. 学生个人错题；
8. 后续生成题。

---

# 2. 数据处理总体流程

```text
原始文件
 ↓
文件登记
 ↓
解析
 ↓
切分
 ↓
结构化抽取
 ↓
知识点映射
 ↓
题型映射
 ↓
质量校验
 ↓
人工/规则确认
 ↓
持久化
 ↓
向量索引
```

---

# 3. 真题结构化

每一道真题必须尽量拆成独立 Question。

至少保存：

```text
学校
科目代码
年份
题号
分值
题干
知识点
题型
难度
答案/解析
来源
```

一个题可能对应多个知识点。

例如：

```text
HIT 801 2024 Q5

knowledge_points:
- 根轨迹
- 分离点
- 稳定范围

question_type:
COMPREHENSIVE_CALCULATION
```

---

# 4. 知识点映射

推荐两阶段：

## 第一阶段：规则 + LLM 候选

LLM 输出：

```json
{
  "candidate_knowledge_ids": ["K-RL-03", "K-RL-05"],
  "reason": "...",
  "confidence": 0.82
}
```

## 第二阶段：校验

结合：

- 题目关键词；
- 标准答案；
- 讲义相关章节；
- 已有同类题；
- 人工确认。

不要让 LLM 直接覆盖正式标签。

---

# 5. 题型分类

题型必须和知识点分开。

例如：

```text
知识点：
稳态误差

题型：
给定输入与系统类型求稳态误差
```

另一个题：

```text
知识点：
稳态误差

题型：
干扰输入引起的稳态误差
```

未来针对性刷题很依赖题型粒度。

---

# 6. School Model 数据构建

由结构化真题统计：

```text
knowledge_frequency
question_type_frequency
year_distribution
score_distribution
difficulty_distribution
co_occurrence
```

推荐保留原始计数，不要只存百分比。

例如：

```text
knowledge_id = K-RL-03
count = 8
total_questions = 120
frequency = 0.0667
years_covered = 10
```

避免未来统计口径变化无法重算。

---

# 7. 讲义 / 教材知识库

作用不是替代 Question Pool。

主要用于：

- 错题诊断；
- 薄弱点证据检索；
- 概念解释；
- 前置知识定位。

RAG 文档 chunk metadata：

```text
document_id
source
chapter
knowledge_ids[]
page
section
text
version
```

Agent 检索时尽量基于：

```text
knowledge_id
+
semantic query
```

避免纯向量全库乱搜。

---

# 8. 学生私有错题

学生错题进入系统后保存：

```text
原题
学生答案
正确答案
学生复盘
来源
做题时间
知识点候选
错误类型候选
```

必须区分：

```text
原始用户数据
AI 推断数据
人工确认数据
```

例如：

```text
error_type_source = MODEL_INFERRED
```

以后用户修正后：

```text
error_type_source = USER_CONFIRMED
```

---

# 9. Question Pool

查询接口至少支持：

```text
search_questions(
    knowledge_ids,
    difficulty,
    question_type,
    source_type,
    school,
    year_range,
    exclude_question_ids,
    limit
)
```

Practice Planner 不直接访问数据库表，走领域工具。

---

# 10. 生成题的数据生命周期

LLM 生成的题不能直接进入正式题库。

状态：

```text
DRAFT
VALIDATING
VALID
REJECTED
REVIEW_REQUIRED
```

生成题必须记录：

```text
generator_model
prompt_version
source_template
generation_seed
validation_result
```

后续发现错误可以追踪来源并批量下线。

---

# 11. 数据版本化

目标院校考情可能持续更新。

例如新增 2027 真题后：

```text
SchoolProfile v3
→ SchoolProfile v4
```

不要覆盖旧版本。

已有计划继续绑定生成时使用的版本。

下一轮 Replan 可以选择升级到最新版本，并记录迁移原因。

---

# 12. 数据质量指标

至少监控：

- 真题解析成功率；
- 题目知识点标签准确率；
- 题型分类准确率；
- 真题重复率；
- 解析缺页率；
- solution 缺失率；
- generated question 校验通过率；
- RAG evidence 命中率。

---

# 13. 推荐初始技术

MVP：

```text
PostgreSQL
+
对象存储/本地文件
+
LanceDB / pgvector（二选一）
```

不要第一版同时上多个向量库。

真题/题目元数据必须以关系数据库为权威来源。

向量库只负责语义召回，不负责“权威事实”。
